# Work triage

1. Resolve the workspace and project scope before changing tasks.
2. Load backlog, todo, in-progress, and in-review tasks. Continue through pages when the first page is not enough.
3. Group likely duplicates by outcome, not title wording alone. Read both tasks before proposing a merge or cancellation.
4. Flag stale in-progress work, missing owners, unclear descriptions, overdue dates, and blocked dependencies.
5. Recommend an ordered queue using stated priority, due dates, dependencies, and current ownership.
6. Present proposed status, priority, assignee, or cancellation changes before applying them unless the user already gave exact instructions.
7. Never delete tasks during triage.

Return task identifiers with each recommendation so the user can review the source.
